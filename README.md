## 1. 一句话定位

**EGPR 不重新发明 VOI，而是研究如何把自然语言证据转化为适合信息获取决策的状态：保留仍会影响查询价值的解释不确定性，避免在证据尚不足时提前关闭澄清与验证路径。**

完整 EGPR 继续使用成熟的结构化信息获取、约束检查、筛选和增量维护。潜在新增贡献不是这些算法的重新命名，而是一个可训练的语言接口，以及对其决策后果的可归因验证。

当前研究问题是：

> 在 Web 服务检索与组合推荐中，如何训练证据解释模块，使其既忠实于已披露的信息，又减少对后续查询价值、停止时机和方案筛选的扭曲？

### 1.1 已确定的项目选择与尚未成立的主张

| 项目 | 当前决定或状态 |
|---|---|
| 项目路线 | 采用完整版 EGPR，不改回简化版，也不切换到 UCPR |
| 仓库 | 使用既有 `shiiiikw/foodpath-mas-uq` |
| 应用能力 | 保留 nutrition QA、food knowledge QA、服务检索、个人获取规划及供给侧接口 |

## 2. 这几轮讨论形成了哪些修正？

早期 EGPR 主要围绕信息价值筛选和增量更新展开。文献讨论指出，VOILA、真值维护、增量规划及元推理已有直接相关机制，因此不能再把“VOI＋筛选＋缓存”当作默认的新算法。

随后，项目转为检验成熟技术在 FoodPath 中的应用价值，并把“语言如何进入决策状态”识别为一个需要单独诊断的接口。新增训练也由一般的状态更新，进一步收紧为对查询价值和停止决策负责的证据解释。

| 阶段 | 曾经的关注点 | 当前处理方式 |
|---|---|---|
| 完整方案 VOI | 根据完整方案收益决定问什么 | 保留为成熟决策基础，不作为新理论 |
| 筛选＋增量修订 | 减少反事实计算和重复规划 | 保留在完整版中，评价应用收益与开销；不将缓存本身当创新 |
| 成熟方法的 FoodPath 应用 | 比较状态管理、决策策略和计算复用 | 保留为独立的系统与实证贡献路径 |
| 小型状态更新器 | 选择一个正确的状态增量 | 作为普通监督基线；不再是新增方法的最终定义 |
| 当前训练候选 | 保留会影响信息获取的多种证据解释，学习减少查询价值失真 | 当前优先验证的训练方向 |

**不再同时把这些阶段包装成多个并行“新方法”。** 当前方案是在同一个完整版 EGPR 中，用成熟算法承担结构化决策，用小型学习模块研究语言到决策状态的适配问题。

## 3. 论文故事：已有方法边界 → 决策后果 → 训练需求

### 3.1 任务为什么需要信息获取？

FoodPath 的目标不是回答一个孤立的食物知识问题，而是根据用户限制和服务规则，检索、筛选并组合能够支持完整需求的服务。用户时间、资格、证件和获取条件可能尚未明确，服务来源也可能有适用范围或例外条款。

因此，系统需要决定哪些信息值得继续询问、哪些应查证外部来源，以及何时能够给出有证据支持的推荐。只知道“还有不确定性”不够，必须判断它是否影响当前任务。

### 3.2 成熟 VOI 解决什么，假设什么？

VOI 提供比较信息收益与获取成本的决策原则。VOILA 等结构化方法还利用概率依赖关系和计算复用降低评估开销。对话中采用的文献边界是：这些方法在明确的变量、观测语义和概率模型上工作；自然语言如何被解释为这些变量的取值，不是原特征获取算法本身要解决的语言学习问题。[R1]

不能把相关工作描述成“不考虑成本”“不会处理相关变量”“不考虑后续任务收益”。也不能声称一般 VOI 或 POMDP 理论无法处理不确定观测；软证据、belief 更新和概率对话状态已有成熟先例。[R2–R5]

**我们针对的是迁移接口可能违反观测假设，而不是否定 VOI 理论。**

### 3.3 在自然语言接口处，什么前提可能被违反？

以下两件事并不等价：

```text
真正观测到：X = x。
收到一段文本：r 可能支持 X = x，但其对象、力度或范围尚不明确。
```

例如，用户回答：

> 我一般四点左右下班，过去应该来得及。

这不自动等于“可以在某个指定截止时间前到达”。系统还需要理解下班时间、路程、截止时间及“应该”的不确定含义。

若接口直接输出唯一解释，再把它写成已确认事实，就可能把解释不确定性从后续决策中删除。这里不是信息完全缺失，而是信息存在、解释仍未充分确定。

### 3.4 为什么不是普通字段错误？

本研究要检验的因果链是：

```text
仍然含糊的公开证据
    → 被转成唯一且确定的状态
    → 决策器低估仍然存在的不确定性
    → 低估继续澄清或查证的价值
    → 提前停止、错误降低查询优先级，或在不适用的前提下排除查询
    → 方案未完成、反复被检查器退回，或增加后续修复成本
```

这类错误不仅影响当前状态，还可能使系统放弃纠正该状态所需的信息获取行动。

以上是**待验证的机制假设**，不是已观察到的普遍结论。完整 MAS 中的检查和恢复可能抵消部分影响，因此不能删除这些能力来制造失败。

### 3.5 为什么训练模块必须由这一机制推出？

普通语义监督主要关心解释或字段是否正确；不同字段错误却可能造成不同的信息获取后果。一个措辞差异可能不影响任何方案，而漏掉适用对象、否定或例外条件，可能直接改变是否还应该询问。

因此，训练目标应当同时约束证据忠实性与查询决策，而不是只让模块更会输出 JSON，或笼统奖励最终任务成功。

## 4. 一个说明机制的反例

以下数值只用于说明逻辑，**不是数据统计、模型校准结果或训练概率标签**。

假设在两个互斥情形中，方案 A、B 分别正确；正确收益为 1，错误为 0。当前公开信息对应的示意 belief 为：

$$P(A\text{ 正确})=0.6,\qquad P(B\text{ 正确})=0.4.$$

立即选择的最优期望收益是 $0.6$。一个完美区分两种情形的澄清问题成本为 $0.1$，因此：

$$\operatorname{NetVOI}(q)=1-0.6-0.1=0.3.$$

继续询问有价值。

若接口把最可能的解释直接当作确定事实，决策器相当于收到 $P(A\text{ 正确})=1$，于是计算：

$$\widehat{\operatorname{NetVOI}}(q)=1-1-0.1=-0.1.$$

同一个问题由值得询问变成不值得询问。错误不在 VOI 算术，而在观测状态比实际证据更加确定。

这一例子只能证明现象可能发生。它不证明真实文本的解释概率就是 0.6，也不证明 FoodPath 中频繁出现这一问题。实际工具可能无法完美回答问题，训练和评估必须使用相应的观测模型。

## 5. 任务定位与范围

### 5.1 WWW 定位：交互式 Web 服务检索与推荐

中心任务是：**从来源可追溯的服务目录和用户交互中，检索、筛选、组合适用服务，并通过必要的信息获取完成推荐。**

Web 不是装饰性的检索工具。服务页面中的资格、例外、适用对象与时间范围，应当真实影响候选集合和后续查询。仅使用网页数据或调用 API，不足以建立 Web 研究贡献。

静态、带版本的来源快照可以作为可复现实验环境；不要求为投稿开发网站，也不把静态评估写成实时服务可用性的验证。具体 WWW track 名称、格式和截止时间需要独立核对官方信息。

### 5.2 三层状态必须分开

| 层次 | 含义 | 不得混淆 |
|---|---|---|
| 世界状态 | 条件在任务环境中是否成立 | 隐藏真值不能直接进入 Agent 输入 |
| belief | 根据当前公开信息，对可能状态的建模 | 高概率不等于已经有证据确认 |
| 证据与交付状态 | 是否有充分依据支持某条件，是否允许无条件推荐 | 不能仅因模型置信度高就标为已核实 |

条件状态继续采用 `supported / refuted / unknown`；来源冲突额外记录。`unknown` 不等于 `refuted`，未检索到要求不等于明确没有该要求。

### 5.3 数据支持决定结论范围

没有交通衔接标签，就不声称验证了完整路线可行性；没有数量或容量标签，就不声称满足了实际多日食物需求或实现动态供给优化。营养数据库不是实时 pantry 库存。

供给侧功能继续保留。第一篇论文的评价终点只覆盖来源实际支持的服务条件，不为“完整系统”补造库存、容量或实际领取结果。

## 6. 完整版 EGPR 架构：不删原有模块，只增加一个学习接口

| 模块 | 职责 | 贡献定位 |
|---|---|---|
| M1：Evidence-grounded plan state | 维护完整方案、条件、来源、作用范围、belief 与证据义务 | 必要系统表示 |
| M2：Decision-critical screening | 在有效假设与界限下减少不必要的反事实评估 | 成熟机制的适配和实证评价 |
| M3：Incremental plan revision | 新证据后更新受影响的条件、方案、缓存与证书 | 成熟增量维护的适配 |
| M4：Budgeted information acquisition | 比较询问、查证、搜索／修订和不同终止输出 | 成熟 VOI 的任务实现 |
| M5：Full MAS integration | 保留 Planner、Reviewer、Coordinator、工具、检查与恢复 | 正常完整工作流 |
| T：Query-value-aware evidence interpretation | 学习保留与查询决策有关的解释差异 | 当前待验证的新增学习机制 |

```text
用户请求 + Web 服务来源
          ↓
已有公开历史、当前方案与证据状态
          ↓
固定候选解释生成器
          ↓
小型可训练解释评分器 T
          ↓
解释权重 + 未解决状态 + 来源与作用范围
          ↓
共同 belief 构建与更新
          ↓
原有 EGPR：筛选 / VOI / 增量更新 / 预算控制
          ↓
ASK / VERIFY / SEARCH-REVISE / 合法终止输出
          ↓
共同最终检查器 → 通过，或退回继续修订
```

保留原有必要上下文和三角色拓扑，不为“完整版”机械增加常驻 Agent 数量。所有主对照获得相同原始信息、工具、最终检查器和恢复机会。

### 6.1 证书边界

训练模块的分数不是形式化证书。依赖它构造的状态若有语义错误，后续证明最多在错误输入模型内成立，不能宣称对真实服务具有保证。

严格筛选需注明固定候选、目标、观测模型和依赖假设；启发式分数不计为 certified pruning。证据、候选池、概率关系或来源版本变化后，应检查证书和缓存失效。

一步 VOI 的证书不保证保留最优多轮策略；多个问题可能互补。已确认事实与软证据的条件独立关系也不一定相同，不能把硬观测下成立的剪枝规则直接套到多解释混合状态上。

## 7. 小型训练模块的具体规格

### 7.1 输入

$$x_t=(h_t,S_t,e_t,\mathcal P_t).$$

其中 $h_t$ 是当前公开历史，$S_t$ 是已有状态，$e_t$ 是新用户回答或工具反馈，$\mathcal P_t$ 是当前候选方案及约束。模块不能读取隐藏目标资源或尚未披露的用户事实。

### 7.2 候选解释

固定生成器产生有限候选集合 $\mathcal M_t=\{m_1,\ldots,m_K\}$。每个解释描述的是文本支持的更新，而不是任意有利于完成任务的状态。

```text
Interpretation:
  interpretation_id
  subject_scope             # 哪位用户、哪项需求、哪个资源
  affected_condition_ids
  proposed_update           # 补充、修正、否定、保留未知等
  evidence_ids_and_spans
  unresolved_alternatives
  affected_plan_ids
```

候选应覆盖可能改变决策的对象、范围、证据力度和更新关系差异。明确的“不更新／仍未解决”也是候选行为，但不能成为规避所有判断的默认答案。

报告正确或证据相容解释的候选覆盖率。候选缺失时，评分器无法恢复正确解释；不能把候选生成优势误归因于训练损失。

### 7.3 模型规模

优先使用冻结的文本编码器和小型可训练评分头，对同一候选集合评分。具体编码器、参数量、训练样本数和算力需求待实现后登记。

不把十天窗口变成同时训练完整 Planner、用户模拟器、VOI 估计器和多轮 RL 控制器。若后续更改模块形式，必须保持普通监督与查询监督对照的模型容量和训练预算一致。

### 7.4 输出与 belief 更新

输出不是唯一的最大分解释，而是候选权重及剩余不确定性：

$$w_k=p_\phi(m_k\mid h_t,S_t,e_t,\mathcal P_t),\qquad \sum_k w_k=1.$$

在给定一致的候选状态模型时，可构成：

$$b_\phi(z\mid h_t,e_t)=\sum_k w_k\,b_k(z\mid h_t,e_t,m_k).$$

这是一种实现表示，不意味着 softmax 权重自动具有真实概率含义。需要明确候选的重叠、遗漏、先验及后验语义，避免重复计入同一证据或先验；不能只保留独立边缘分布而丢失重要相关性。

**先合成当前尚未解决的不确定性，再评估查询。** 不能先假设每种解释已经确定、分别计算其 VOI 后再平均，否则可能删掉澄清问题本来要区分的解释不确定性。

解释权重仅用于 belief 和行动评价，不能越过共同证据检查，把高权重状态直接升级为已核实事实。

### 7.5 与上一轮“状态更新器”的区别

普通更新器可以作为基线输出唯一更新；当前候选模块必须保留仍有决策意义的多个解释。新增研究点不是简单维护更多假设，而是学习哪些解释差异不能在查询价值计算之前被丢弃。

## 8. 决策器与训练目标

### 8.1 VOI 仍然是共同决策原则

令 $V(h)$ 为在当前公开历史下，合法终止输出的最优预期效用。一阶查询价值可以写为：

$$Q(q\mid h)=\mathbb E_{o\sim p(o\mid q,h)}[V(h\oplus(q,o))]-V(h)-C(q).$$

该式是既有 VOI 的任务实例化，不是本项目的新公式。停止作为显式行动参与比较；查询结果允许具体回答、无法回答、仍未解决和来源冲突。

原始任务里“最佳方案 ID 没变”不等于“无需查证”。查询还可能补齐该方案的证据义务，使原先不允许的无条件交付变成合法输出。

### 8.2 两项训练目标

$$\mathcal L(\phi)=\mathcal L_{\mathrm{evidence}}(\phi)+\lambda\mathcal L_{\mathrm{query}}(\phi).$$

| 目标 | 监督内容 | 不能替代什么 |
|---|---|---|
| $\mathcal L_{\mathrm{evidence}}$ | 解释与公开证据的一致性、作用范围、否定、保留未知及适当校准 | 不能仅奖励格式正确或输出唯一字符串 |
| $\mathcal L_{\mathrm{query}}$ | 解释是否扭曲查询排序、停止判断或有效信息的保留 | 不能仅奖励对同一教师的拟合，或鼓励篡改事实来提高成功率 |

允许多个证据相容解释，不将所有样本强制变成单标签。没有可信分布标签时，不声称掌握了“真实语义后验”；可使用部分标签、相容性监督和单独的决策诊断。

查询监督的第一版可在冻结的、具有可靠参考状态与观测模型的样本上，离线计算行动价值或排序，再训练评分器减少相应决策错误。具体采用排序损失还是价值误差，需要在开发阶段冻结，不在测试后择优选择。

**STOP 必须进入训练和评价。** 只惩罚过早停止而不惩罚无价值的继续询问，会把模块推成一个更保守、却未必更有效的策略。

### 8.3 为什么不直接奖励最终成功？

最终成功可能受候选生成、检索、工具错误和其他 Agent 行为影响，不能直接证明证据解释学得正确。只用成功奖励还可能鼓励把含糊事实解释成更容易完成任务的状态。

因此必须保持事实／证据监督，并分别测量解释、查询决策和最终任务表现。决策感知训练已有先例；本项目要验证的是针对这一迁移失败机制的具体学习目标与收益。[R3, R9]

## 9. 训练标签：必须先解决监督可信度

这是 WWW 模拟审稿中最关键的可靠性问题之一。

### 9.1 三类标签分开管理

| 标签 | 合法来源 | 可支持的结论 |
|---|---|---|
| 文本支持的解释／更新 | 已披露文本、可核查来源字段、可靠的逐轮标注 | 证据解释能力 |
| 参考查询排序／价值 | 明确的状态、成本及观测模型，或单独标明的近似教师 | 对该模型或教师的决策逼近 |
| 最终方案质量 | 独立评分口径、必要条件与公开支持证据 | 端到端应用收益 |

查询参考值来自近似教师时，要记录模型、假设和误差范围。测试不能只验证学生是否复现同一教师的排序，还要评价独立终点。

### 9.2 隐藏真值与公开证据

训练集的隐藏真值可以用于适当定义的监督或任务结果评价，并不天然构成泄漏。但不能把隐藏事实塞给推理系统，也不能因为某次含糊表达背后恰好对应一个真值，就将该表达标成唯一确定解释。

相同公开历史下的规范化状态，只能包含已经披露的事实。它是诊断参照，不是把完整用户档案提供给某个方法的权限。

### 9.3 对无法回答的问题不造标签

若真实数据没有备选查询的回答、继续交互的结果或可信概率模型，就不能从一条观察到的对话推导所有行动的真实价值。

受控模型可以提供精确或可枚举标签，但结果必须标为受控机制诊断。自然轨迹可支持的语义标签、教师排序和端到端结果分别报告，不能混成真实用户行为结论。

### 10.1 可继承资产：数字来自先前记录，本次未重新核验

| 资产 | 历史记录 | 本轮用途与边界 |

| 既有失效运行 | 曾存在最终检查未强制回退的问题 | 保留为历史，不纳入新效果比较 |
| API 状态 | 曾记录额度耗尽 | 恢复状态未核验；写 README 不等于授权新调用 |
| ConditionalQA / InSCIt | 已做部分数据与标签适用范围核查 | 不直接充当配对交互收益或查询价值真值 |

### 10.2 唯一目标资源与多正确方案

先前讨论指出，原任务可能按唯一目标资源构造标签。[R7] 应保留原生资源选择指标，但不能仅凭命中目标 ID 就认定形成了有证据支持的完整方案。

反过来，不能在缺少替代方案有效标签时，声称已经评价了多正确方案选择。初始有多个候选与最终存在多个正确完整方案，是不同的数据性质。

### 10.3 拆分规则

先按来源机构、资源共享关系和相关文档形成分组，再拆训练、开发和测试。同一任务的不同轮次、改写或模拟重复不得跨组泄漏。必要时合并历史 45 组，并报告实际有效组数。

自然任务、受控反例和语言改写要单独标记。增加同源轮次不会增加相应数量的独立来源，不能靠改写扩大独立样本量。

### 10.4 预算与权限

不重跑已完成的付费实验来重新寻找显著结果。启动任何新模型实验前确认访问、预算和恢复协议；所有失败、重试、候选生成、教师标注和训练开销计入日志。密钥只从合法本地环境读取，不写入 README、配置、日志或 Git。

## 11. 研究问题与可证伪假设

| 问题 | 当前假设 | 不支持该假设的结果 |
|---|---|---|
| RQ1：机制是否存在？ | 自然出现的证据过早确定化会扭曲查询／停止决策，并在完整工作流中造成损失 | 仅人工反例有问题；正常检查和恢复已经消除影响 |
| RQ2：软证据是否已足够？ | 保留解释不确定性优于强点估计接口 | 合理校准的点估计或普通软证据已达到相同性能 |
| RQ3：特殊训练是否必要？ | 查询价值监督优于相同模型、数据和预算下的普通监督 | 所有收益可由普通训练、更大候选集或保守阈值解释 |
| RQ4：端到端是否有价值？ | 在相同交互预算下提高有证据支持的完成率，或在相当质量下减少信息获取 | 仅字段指标改善；额外计算或提问抵消收益 |
| RQ5：适用边界是什么？ | 收益与未见来源、范围歧义和需求组合有关，并存在可解释边界 | 只在少数熟悉模板上有效，或结构维护始终不划算 |

不要求发明新的 uncertainty estimator，也不要求击败相同模型和目标下的精确最优 VOI 策略。最优策略是参照，不能被当成需要超越的错误基线。

## 12. 实验组织：先诊断，再训练，再完整运行

### 12.1 E0：离线机制与接口正确性

用明确标记的受控实例检验混合 belief、查询观测、停止比较和筛选前提。包括已知信息下不应多问、不同解释间澄清有价值、问题互补、来源冲突和未知不等于否定等情况。

同时检查增量结果与完整重算的一致性、缓存失效、原始来源的作用范围，以及共同最终检查器是否返回可恢复错误。此层不证明真实用户收益。

### 12.2 E1：同公开状态的配对诊断

固定一批在正常任务中遇到的公开状态、候选资源、候选解释、查询和成本模型，只改变证据解释方式，比较查询排序与停止选择。

规范化状态不得添加未披露事实。每个判断保存原文、来源、候选解释、belief、查询价值和最终动作。相同状态上的结果用于机制归因，不冒充完整交互收益。

### 12.3 E2：完整 MAS 主实验

在来源隔离的固定任务上运行完整工作流。每组有同样的工具、必要上下文、查证、修订、条件输出及恢复机会。

记录所有任务，不筛掉失败任务；预算耗尽时明确输出未解决条件。若方法的后续轨迹不同，按同任务配对分析，但不能声称不同轨迹拥有完全相同的后续信息。

### 12.4 E3：迁移与边界

优先测未见服务机构、来源或需求组合。第二模型或跨领域实验只在核心实验完成且预算允许时扩展。未执行的扩展标为未执行，不写成泛化结论。

## 13. 对照系统：防止收益被普通方法解释

### 13.1 训练模块的核心对照

| 编号 | 解释接口 | 主要作用 |
|---|---|---|
| B0 | 强点估计／确定性解释＋共同 VOI | 检查过早确定化是否存在；不故意削弱其校准或恢复能力 |
| B1 | 普通多假设／软证据解释＋共同 VOI | 检查保留不确定性本身是否足够 |
| B2 | 普通证据监督训练的软解释模块＋共同 VOI | 检查是否只是任务训练有效 |
| B3 | 同一模块、同一数据，加查询价值监督＋共同 VOI | 当前拟议方法 |
| D0 | 同信息的规范化公开状态 | 语言接口诊断参照，不作为有部署成本优势的实际方法 |

B1、B2 应有合理的温度／概率校准和停止阈值调节机会，且只在开发集调节。模型容量、训练样本、候选解释覆盖、查询候选与工具权限保持匹配。

这里**不能要求各解释模块输出相同 belief**：belief 的变化正是被研究机制。但观测模型、下游决策规则和可见信息应尽可能一致，并记录必要差异。

### 13.2 成熟系统与普通替代解释

保留完整自适应 MAS、带结构化状态的 MAS，以及强 Full-Plan VOI＋Checker＋Dependency Cache。后者不能被实现成每次无条件从头运行的弱对照。

将同一训练模块接入强 VOI 系统，区分语言接口贡献与 EGPR 独有贡献。若所有决策器获得相同收益，应把主要贡献归于接口，而不是声称 EGPR 的筛选算法独有。

采用 VOILA 思想的适配实现必须记录与原始问题、观测模型、效用和算法的区别，不能把一个自定义简化基线称为完整复现。

### 13.3 排除“只是更保守”

除固定预算比较外，报告完成质量与提问／查证成本的权衡。允许普通方法在开发集调停止阈值，不能用未校准基线衬托新模块。

同时评价错误停止和无价值继续询问。提高准确率却消耗更多交互，不自动说明查询价值判断更好。

## 14. 消融：保留完整版，并分开归因

### 14.1 学习机制消融

| 设置 | 保留多解释 | 证据监督 | 查询监督 | 检验内容 |
|---|---:|---:|---:|---|
| 完整候选模块 | 是 | 是 | 是 | 总体效果 |
| 去掉查询监督 | 是 | 是 | 否 | 特殊训练目标是否有独立价值 |
| 推理时压成单一解释 | 否 | 与完整模块相同 | 与完整模块相同 | 收益是否依赖保留解释不确定性 |
| 未训练软解释接口 | 是 | 否 | 否 | 是否仅维护多个假设就已足够 |

压成单一解释的消融用于检查机制，不替代经过合理调节的强点估计主基线。另行报告候选覆盖、概率校准、停止阈值及总体语义准确率，避免将其他变化误归因于查询监督。

### 14.2 完整 EGPR 的 2×2 消融

| 设置 | 决策关键筛选 | 增量更新 |
|---|---:|---:|
| Full EGPR | 是 | 是 |
| Screening only | 是 | 否 |
| Incremental only | 否 | 是 |
| Neither | 否 | 否 |

这一组固定解释模块、belief、候选方案和证据接口，比较成熟组件的效率与状态一致性。它证明组件在 FoodPath 中是否有用，不自动证明组件新颖。

核心训练比较与这组消融可以分阶段运行，不要求立刻做所有配置的笛卡尔积；完整版模块本身不因此删除。

## 15. 评价：解释 → 查询 → 任务的三层证据

### 15.1 解释层

评价对象／需求作用范围、取值与否定、错误覆盖旧条件、未知被错误确定化、证据相容解释覆盖、候选覆盖及适用的校准指标。

没有可信概率标签时，不声称计算了相对于真实语义后验的校准误差。概率评分只能使用与数据性质一致的目标和明确解释。

### 15.2 查询层

评价查询排序与参考价值的偏差、错误停止、无价值继续、有效查询被错误排除，以及共同检查器驳回后的额外修订。

“错误停止”等标签必须说明参照：精确受控模型、可靠任务规则，还是近似教师。参考模型下有正价值，不等于已经观察到真实用户交互收益。

候选权重到查询决策的变化需要保存可审计轨迹。若字段准确率提高但行动没有改变，就不支持查询机制改善的主张。

### 15.3 任务层

主要报告**预算内有证据支持的完整推荐完成率**，并保留原生 benchmark 指标。另报事实／条件正确性、未解决义务、条件输出和无法解决的终止。

成本包括询问信息项、独立信息项、用户轮次、工具调用、模型调用、tokens、延迟，以及模块训练／候选生成／教师标注／结构维护开销。将训练的一次性成本与每任务推理成本分开，不隐去前者。

共同检查器若使所有方法的无依据交付率都为零，这个零不能作为 EGPR 的优势；应比较完成、被驳回、恢复和预算耗尽。

### 15.4 条件答案不等于消除负担

最终答案中的条件分支、用户仍需自行判断的事项及未解决必要条件，应与显式提问分开统计。问题数减少但条件文本增多，不自动意味着交互负担下降。

这些是离线代理指标，不是对真实认知负担、信任或获得食物结果的测量。

## 16. 统计、可复现性与成功判定

主分析按来源／资源依赖组配对，报告组数、均值或适当分布、配对差异与区间。重复对话和同源改写不作为新的独立组。样本有限、区间宽时，不把“不显著”写成“没有降低质量”。

预先固定训练／开发／测试分组、模型快照、候选数、预算、代价定义、训练损失、随机种子、阈值及主指标。数字配置尚未确定的条目保持待定，不在 README 中虚构已经冻结的参数。

| 判定层 | 足够支持什么 | 不足以支持什么 |
|---|---|---|
| 受控反例通过 | 实现与所声明的逻辑一致 | 自然场景频繁失败 |
| 自然同状态诊断成立 | 解释方式确实影响查询决策 | 完整任务一定改善 |
| B3 优于 B2 | 特殊训练可能有额外作用 | 没有匹配数据／预算时的因果归因 |
| 端到端预算曲线改善 | 当前任务环境中的应用收益 | 真实用户负担与实际食物获得 |
| 未见来源表现稳定 | 所测试分布上的迁移证据 | 对所有服务领域的一般保证 |

若 B1 已解决问题，结论可以是成熟软证据方法足够；若 B2 接近 B3，不主张查询监督必要；若结构维护开销抵消收益，报告适用边界。负结果保留，不临时换任务或损失来制造显著性。

## 17. WWW 模拟审稿：当前结论与接收条件

### 17.1 当前结论

先前模拟审稿的倾向是 **Weak Reject，具备转为 Weak Accept 的路径**。这不是对真实投稿的官方评分，也不是接收概率。

主要原因不是模块太小，而是尚未证明它超出“多假设状态跟踪＋常规监督＋决策感知训练”的普通组合，同时监督来源与 Web 端到端收益仍不完整。

### 17.2 四个关键质疑

| 质疑 | 论文需要给出的回答 |
|---|---|
| Web 关联不足 | 明确解释服务来源与规则怎样改变检索、筛选、查询和推荐，而非只说使用网页数据 |
| 新颖性不清 | 与软证据、概率对话状态、POPCORN／决策感知学习及近期 VOI 对话方法区分 |
| 监督可信度不足 | 分开证据标注、参考查询价值与独立任务结果；防止循环教师评价 |
| 只是更保守或数据过窄 | 匹配交互预算、调节强基线阈值；同时测过早停止与多余追问，并做来源隔离 |

### 17.3 改变推荐所需的三项证据

**第一，正常完整工作流中存在该失败链。** 不仅是手工反例，而是自然证据的过早确定化确实改变行动，并造成可观测损失。

**第二，查询价值监督优于普通软证据与普通监督。** 差异不能由候选覆盖、容量、训练数据或更保守阈值解释；整体语义准确率与决策性错误需要同时分析。

**第三，Web 服务任务端到端受益。** 在来源隔离的测试上，达到更好的可靠性—信息获取—推理成本权衡。

达到这些条件，可以形成“失败分析＋有独立作用的学习适配＋应用证据”的接收理由。无法达到时，不因系统复杂或加入训练就提高新颖性主张。

## 18. 论文叙事草案

### 18.1 中文逻辑链

**任务要求。** 自然语言服务检索需要把用户限制与 Web 规则组合成完整方案。必要条件尚未明确时，系统必须主动询问或查证，因此信息获取是完成任务的一部分。

**已有能力与边界。** VOI 能比较信息收益和成本，结构化方法能复用依赖关系，但这些能力建立在正确的状态和观测建模之上。语言接口必须决定文本支持什么，不能把可能解释直接写成已确认观测。

**待验证的失败。** 若接口过早消除解释不确定性，系统可能低估验证该解释的价值，并提前关闭仍有用的澄清路径。因此，只优化一般字段准确率未必足以保护后续信息获取决策。

**方法与验证。** EGPR 保留成熟的信息获取和增量维护，加入小型查询价值感知证据解释模块。通过证据一致性和查询后果监督，检验是否能减少决策性解释错误，并用强软证据基线、同信息诊断和完整任务实验验证独立作用。

### 18.2 英文研究定位草案

> Web service navigation requires agents to combine user constraints with service-specific requirements, many of which become available only through interaction and source verification. Value-of-information methods provide a principled basis for choosing these information-acquisition actions, but their decisions depend on how observations are represented. We hypothesize that collapsing ambiguous language into a single certain state can suppress the estimated value of further clarification, causing an agent to stop before decision-relevant uncertainty has been resolved.
>
> EGPR retains established structured information acquisition and incremental state maintenance, while adding a lightweight evidence-interpretation module trained to preserve distinctions that affect query value and stopping decisions. The proposed supervision combines evidence consistency with information-acquisition consequences. Evaluation will distinguish gains from ordinary soft-evidence tracking, task-specific supervision, and conservative stopping, and test whether the resulting decisions improve evidence-supported service recommendations under matched budgets.

这段是 proposal 级文字；在实际结果出现前不改写成 “we demonstrate / experiments show”。正式稿还需要为相关工作补充经过核验的引用。

### 18.3 当前可以写与不能写的贡献

| 可以作为研究目标或条件性贡献 | 目前不能写成已成立的结论 |
|---|---|

## 最终原则

**我们要证明的不是“EGPR 加了训练”，而是：在成熟的信息获取系统中，训练语言接口保留哪些解释差异，才能避免扭曲后续查询与停止决策，并在真实来源支撑的任务环境里形成额外价值。**

方法很小可以成立；方法很复杂也可能没有额外贡献。判断依据始终是可靠标签、强基线、完整工作流和可归因的实验证据。
