## 已实现

- M1：有作用范围和来源的条件、证据、候选完整方案；区分未知、否定和冲突。
- M2：精确有限联合分布下的一步 VOI、严格优势剪枝、数值 witness 和版本化证书。
- M3：条件及 belief 依赖缓存、变更影响报告、候选池变化后的失效处理。
- M4：受控的多轮 Ask/Verify、公开候选池更新、预算耗尽和最终检查器。
- M5 第一部分：真实 API 的 Planner–Reviewer–Coordinator，以及一次有预算的检查恢复。
- 模型反事实评估：允许 LLM 选错或失败；其效用下界为 0，证书绑定模型与请求版本。
- 全请求缓存、独立 replicate 编号、追加式费用账本、中断预留、进程写锁和访问恢复。
- 原始 FoodPath 输入资质审计，以及防止旧工具把未知/没有/无偏好混同的类型化适配器。
- 原生任务的逐字段用户适配器：只披露所问字段，隐藏目标与后续替代方案，重复询问计费。

这不是完整 FoodPath 端到端系统。真实来源抽取、实时检索和用户交互、B0/B4
及跨模型家族的正式效果实验尚未完成。

五种方法的最终行动和信息获取次数一致，无无证据提交。
生成器有已获支持的备用方案，所以其 100% completion 只是集成检查，不能当效果。
常数奖励下结构界限可直接算出一些精确值；[完整操作统计](../reports/episodes_v0_3/operation_totals.json)
保留了界限遍历成本，不能把零展开分支写成零计算成本。

真实 API 首批使用 GPT-6 Luna 和 GPT-4.1 Mini 的日期快照：

同批重放复用全部 48 个响应，新增网络调用为 0。
按返回用量与已核对价格的保守估算，首批调用约 US$0.0083；这不是供应商账单。

**模型失败没有被隐藏：** GPT-4.1 Mini 的 52 个枚举终态中，15 次初始提交被
检查器拒绝，恢复后仍有 10 次不合法，另有直接放弃的输出，合计 23 次未交付。
一种观察到的错误是把“没有反证”当成“明确支持”，包括要求为 false 的条件。
最终检查器阻止了这些无依据提交。Luna 初始被拒 1 次、未交付 2 次；Sol
在这批终态中均交付。枚举反事实分支互相关联，不能把这些比例当在线任务成功率。

身份查询成功，账务用量 beta 接口返回 404，无法由此确认充值余额。
所有原始失败及预留保持在本地账本，成功案例可直接复用。
